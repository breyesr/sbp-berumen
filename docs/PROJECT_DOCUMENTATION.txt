Synthetic Persona Web — Technical Documentation
==============================================

1. Product Overview
-------------------
- Goal: help SMBs stress-test ideas with synthetic personas and generate tailored marketing copy.
- Stack: Next.js 16 (App Router), React 19, Tailwind CSS v4, Auth.js credentials auth.
- Data inputs: local JSON/MD under `data/` plus OpenAI APIs for reasoning and embeddings.
- RAG: Postgres + pgvector for hybrid search over persona and global knowledge.

2. UX Entry Points
------------------
Protected routes (`src/app/(app)`):
- `/` (`src/app/(app)/page.tsx`): Idea Stress Test UI.
- `/copywriter` (`src/app/(app)/copywriter/page.tsx`): Copywriter UI.
- `/profile` (`src/app/(app)/profile/page.tsx`): Profile + guided 2FA setup wizard.

Public routes (`src/app/(public)`):
- `/login` credentials login.
- `/register` account creation.
- `/login/2fa` TOTP verification for users with 2FA enabled.

3. Authentication and Protection
--------------------------------
- Auth handler: `src/app/api/auth/[...nextauth]/route.ts`.
- Core config: `src/lib/auth.ts` with credentials provider + JWT strategy.
- Middleware (`middleware.ts`) allows only `/login`, `/register`, `/login/2fa` publicly.
- `(app)` layout wraps pages in `AuthGate` + persistent app shell.
- Session exposes custom claims: `roles`, `apps`, `personas`, `two_factor_enabled`.
- Post-login enforcement: users without 2FA are redirected to `/profile`.
- Protected-page enforcement: `TwoFAEnforcementModal` blocks non-profile protected pages until 2FA setup is completed.

4. Data + AI Flow
-----------------
1) Persona metadata in `data/personas/<id>/persona.json`.
2) Persona/global knowledge ingested into Postgres with `npm run embed`.
3) `src/lib/rag.ts` executes hybrid search (FTS + vector).
4) `/api/stress-test` generates structured critique.
5) `/api/idea-refinement` asks missing-info questions and rewrites pitch.
6) `/api/copywriter` loads rules from `data/copywriter/**` and generates outputs.

5. Key Modules
--------------
- `src/lib/clients.ts`: singleton Postgres/OpenAI clients + env validation.
- `src/lib/personaProvider.ts`: persona loading + RAG context merge.
- `src/lib/totp.ts`: TOTP generation/verification helpers.
- `src/app/api/register/route.ts`: account creation + role assignment.
- `src/app/api/2fa/generate/route.ts`: create secret + QR payload.
- `src/app/api/2fa/verify/route.ts`: verify code and enable 2FA.

6. Configuration and Environment
--------------------------------
Required vars:
- `OPENAI_API_KEY`
- `AUTH_SECRET`
- `POSTGRES_URL_LOCAL` (local)
- `POSTGRES_URL` (Vercel)
- `OPENAI_MODEL` (optional)

Note: `src/lib/clients.ts` validates DB + OpenAI env vars on import.

7. Local Development
--------------------
1. `npm install`
2. `cp .env.example .env.local`
3. `docker-compose up -d`
4. `npm run db:setup`
5. `npm run db:auth:setup`
6. `npm run embed`
7. `npm run dev`

8. DB Scripts and Safety
------------------------
- `db:setup`: resets `documents` table + indexes.
- `db:auth:setup`: recreates auth/RBAC tables; destructive for auth data (`users`, sessions, roles mappings).
- `db:reset`: drops most app/auth tables.

When targeting Vercel DB with `db:auth:setup`, run with `NODE_ENV=production` and explicit `POSTGRES_URL`.

9. Known Limitations and Risks
------------------------------
- Some lint/type issues exist outside the auth flow.
- `db:auth:setup` is not a migration; it resets auth data.
- Legacy endpoints (`/api/scorecard`, `/api/persona`, `/api/berumen`) remain available but are not core UI flows.

10. Reference Commands
----------------------
- `npm run dev`
- `npm run build && npm run start`
- `npm run db:setup`
- `npm run db:auth:setup`
- `npm run db:reset`
- `npm run embed`
